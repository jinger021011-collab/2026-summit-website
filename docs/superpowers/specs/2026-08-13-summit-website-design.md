# 2026 时序数据技术创新大会官网设计规格

> 日期：2026-08-13  
> 状态：待用户复核  
> 需求依据：`docs/requirements.md` V1.0

## 1. 项目目标

建设“2026 时序数据技术创新大会”单页官网，用于大会信息展示、议程查询、嘉宾及合作单位展示、参会指引和报名转化。页面同时适配桌面端和移动端，所有重要活动信息以 HTML 文本输出，并满足键盘访问、减少动态效果、图片异常回退和基础 SEO 要求。

不得自行生成或补写嘉宾、议题、Logo、单位、职务、合作关系、官网链接和活动规则。尚未确认的内容只能采用需求文档指定的处理方式。

## 2. 已确认决策

### 2.1 视觉方向

采用方案 A“主视觉延续＋玻璃信息层”：

- 延续现有主视觉的蓝色空间、彩色折射和玻璃光效。
- 主视觉图片只承担视觉表达，大会名称、主题、日期、地点和参会形式均以 HTML 文本叠加呈现。
- 玻璃信息层保证正文对比度，并在背景图片替换后保持结构稳定。
- 当前只有一张 1920×1080 横版设计稿；开发预览阶段使用响应式裁切，正式移动端主视觉提供后通过 `<picture>` 替换。

### 2.3 Logo 展示规则

- Logo 卡片只显示 Logo 图形，页面视觉界面不显示单位名称文字。
- 每个分组按照素材文件名中的数字升序排列，例如 `1.png`、`2.png`、`3.png`。
- 主办单位、承办单位、协办单位、合作伙伴和合作媒体分别排序，不跨分组混排。
- 承办单位当前只有 `20260813-161454.png`，分组内只有一项，不涉及数字排序冲突。
- 单位正式名称仍作为图片 `alt` 等无障碍信息存在，但不在视觉界面露出；不得根据图形或文件名猜测名称。
- 有正式官网地址的 Logo 才添加链接；未提供地址时使用非链接容器。
- 使用统一 Logo 容器和 `object-fit: contain` 平衡视觉面积，不裁切、不拉伸。

## 3. 信息架构

页面按照以下顺序组成：

1. 全局辅助层：跳至主要内容、吸顶导航、移动菜单、返回顶部。
2. 大会头图 `#top`：大会主题、名称、日期、地点、参会形式和报名按钮。
3. 关于大会 `#about`：大会简介和四项亮点。
4. 大会议程 `#agenda`：主论坛及三个下午分论坛。
5. 嘉宾介绍 `#speakers`：主论坛和案例分论坛嘉宾。
6. 合作伙伴 `#partners`：五类合作单位 Logo 分组。
7. 参会信息 `#guide`：参会须知、交通指南、场地平面图。
8. 报名引导 `#register`：最终报名文案和按钮。
9. 页脚：官方链接、备案信息、联系方式和动态版权年份。
10. 移动端辅助层：离开首屏后出现的固定报名栏。

## 4. 模块设计

### 4.1 全局导航

桌面端使用吸顶导航，左侧为正式 Timecho Logo 或大会标识，中部为模块链接，右侧为“立即报名”。滚动时通过当前可见章节高亮导航项，并用 `scroll-margin-top` 避免标题被吸顶栏遮挡。

移动端使用汉堡菜单。展开时锁定背景滚动，支持遮罩、Esc 和关闭按钮，打开后焦点进入菜单，关闭后焦点返回触发按钮。选择模块后菜单自动关闭并跳转。

### 4.2 大会头图

首屏无需滚动即可看到大会核心信息和报名按钮。背景图上增加受控渐变遮罩与玻璃信息层，确保文字达到 WCAG AA 对比度。主视觉内已有文字不作为内容来源。

“向下了解大会”链接到 `#about`。普通模式可使用轻微循环提示动画；减少动态效果模式下关闭动画和平滑滚动。

### 4.3 关于大会

展示需求文档提供的两段简介和四张亮点卡片。卡片使用同一套简洁线性图标，桌面端四列，窄屏端两列或单列。图标只作为辅助表达，不增加需求之外的活动事实。

### 4.4 大会议程

议程数据只有一个来源，由桌面表格和移动时间轴共同消费：

- 桌面宽屏：主论坛为三列表格；下午分论坛为四列表格；茶歇横跨三个论坛列。
- 约 960px 以下：切换为“主论坛、技术分论坛、案例分论坛（1）、案例分论坛（2）”四个标签，每项按时间顺序显示为卡片。
- 移动标签采用 `tablist`、`tab`、`tabpanel` 语义，支持左右方向键、Home 和 End。
- 议题为主要信息，嘉宾、单位和职务为次级信息；英文标题和长副标题自然换行。
- 陈学峰场次使用本规格第 2.2 节的已确认信息。

### 4.5 嘉宾介绍

仅渲染主论坛和案例分论坛嘉宾，不渲染技术分论坛嘉宾。卡片只包含照片、姓名、单位和职务，不设置详情弹层。

桌面端每行 4～5 张，移动端每行 2 张。不同原图统一显示为固定比例卡片，但保留原文件并通过逐人 `object-position` 配置控制裁切。加载失败时显示统一中性占位图和嘉宾姓名。

### 4.6 合作伙伴

按主办单位、承办单位、协办单位、合作伙伴、合作媒体分组。各组标题保留，卡片内部只显示 Logo，不显示单位名称。空分组不渲染。

当前素材数量为：主办单位 1、承办单位 1、协办单位 3、合作伙伴 12、合作媒体 7。排序以各目录内数字文件名为准。

### 4.7 参会信息

使用“参会须知、交通指南、场地平面图”三个标签，默认显示参会须知。标签支持鼠标、触摸和键盘方向键，切换时控制内容区域的视觉稳定性。

平面图支持点击查看大图，查看层支持 Esc、遮罩和关闭按钮。图片缺失时显示“场地平面图将在会前更新”，不出现破图。

### 4.8 报名引导和页脚

导航、首屏、最终报名区和移动固定栏均跳转到统一配置的官方报名地址，并分别上报 `navigation`、`hero`、`final_cta`、`mobile_sticky`。

移动固定栏在用户离开首屏后出现，最终报名区进入视口后隐藏。返回顶部按钮为固定栏预留空间。

页脚使用需求文档提供的官方链接、备案信息、微信联系方式和动态年份。所有外链新标签页打开并添加 `rel="noopener noreferrer"`。

## 5. 技术架构

- React、Vite、TypeScript。
- 单页锚点导航，不引入路由库。
- CSS Modules 配合全局设计变量，不引入大型 UI 框架。
- 组件局部状态处理移动菜单、议程标签、参会标签和图片查看层，不引入全局状态库。
- `IntersectionObserver` 负责章节高亮、移动报名栏和返回顶部的显示逻辑。
- 内容集中在 `src/data/`，展示组件不重复硬编码议程、嘉宾和合作单位信息。
- `src/lib/analytics.ts` 提供统一事件接口；统计平台未确认前使用安全的空实现。
- 首屏图片优先加载；首屏以下图片懒加载并声明宽高或 `aspect-ratio`。
- 原始素材保留在 `assets/`；如生成优化版本，则输出到 `public/optimized/`。

## 6. 组件及数据边界

- `site.ts`：大会基本信息、报名 URL、导航、页脚链接。
- `agenda.ts`：论坛、时间段、议题、嘉宾引用和茶歇类型。
- `speakers.ts`：嘉宾姓名、单位、职务、照片、裁切位置和显示范围。
- `partners.ts`：分组、排序、图片、正式单位名称、链接。
- `AccessibleTabs`：议程和参会信息共享的键盘及 ARIA 行为。
- `ImageWithFallback`：嘉宾、Logo 和会场图的异常回退。
- `analytics.ts`：屏蔽具体统计平台差异。

数据结构禁止收集或保存报名人的姓名、手机号、邮箱等个人信息；报名只跳转官方页面。

## 7. 响应式和无障碍

重点验证 375、430、768、1280 和 1440px。全局禁止页面级横向滚动。

- 375/430px：菜单、嘉宾双列、议程标签、长标题、固定报名栏。
- 768px：卡片列数和议程时间轴可读性。
- 1280/1440px：首屏完整性、表格可读性、Logo 视觉均衡和最大内容宽度。
- 所有交互支持键盘并有清晰的悬停、焦点和按下状态。
- `prefers-reduced-motion: reduce` 下关闭非必要动画和平滑滚动。
- 焦点顺序与视觉顺序一致，弹层和菜单关闭后恢复焦点。

## 8. 异常处理

- 嘉宾照片失败：中性占位图，不破坏卡片尺寸。
- Logo 失败：保留卡片边界和可访问名称，不显示破图图标。
- 平面图失败：显示会前更新提示。
- 报名链接打开失败：当前页面不报错；URL 集中配置以便替换。
- 未配置官网链接的 Logo：不产生空链接。
- 未确认内容：遵循需求文档和本规格的明确隐藏或待确认规则，不自动生成。
